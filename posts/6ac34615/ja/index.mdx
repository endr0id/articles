## 1. 基礎理論

性質: 強化学習を理解するための土台となる概念群。数学的定義と機械学習全体における位置づけを扱う。

### 1.1 機械学習の3本柱

機械学習は「与えられるもの」によって3つに分類される。

| 種類         | 与えられるもの   | 学習が答える問い | 例                          |
| :----------- | :--------------- | :--------------- | :-------------------------- |
| 教師あり学習 | 入力 + 正解      | 正解を当てる     | 画像分類                    |
| 教師なし学習 | 入力のみ         | 構造を見つける   | クラスタリング、LLM事前学習 |
| 強化学習     | 評価（報酬）のみ | どう振舞うと得か | ゲーム、RLHF                |

強化学習の本質的困難さは以下の3点に集約される:

1. 試行錯誤のみ - 動くまで良し悪しが不明
2. 報酬の遅れ（credit assignment） - 100手目で負けた時、何手目が悪かったか不明
3. 探索と活用のトレードオフ - 基地の最善策 vs より良い手の試行

> 深層学習はこれら3つに共通する「関数の近似器」であり、強化学習固有の概念ではない

### 1.2 Transformerの仕組み

現代AIの土台となるTransformerは、「どの語を見るか」を自分で決める仕組みである。

自己注意機構（Self-Attention）:

- 各語が **Q**（何を探すか） ・**K**（自分は何か） ・**V**（渡す中身）を保有
- QとKの内積が重みとなり、その重みでVを混ぜる
- 参照先は語順ではなく内容の関連度で決定
- 前後を並列計算可能（GPU適正）

自己教師あり:

- 文章の途中を隠して次単語を予測
- 人間のラベル不要、文章が正解を内蔵
- インターネット規模のテキストに対応

創発能力:

- 流暢さ、文法、膨大な世界知識
- 文脈内学習（例を見せるだけでタスク実行）
- 学習時に支持されていない能力が出現

### 1.3 マルコフ決定過程（MDP）

強化学習の問題設定は「エージェントと環境の往復」で記述される。

```text
エージェント（方針π） <-> 環境
    ↓ 行動a
    ← 報酬r + 次状態s'
```

設計者が決定する要素:

| 要素 | 意味                     |
| :--- | :----------------------- |
| S    | 状態空間（何を見せるか） |
| A    | 行動空間（何ができるか） |
| R    | 報酬関数（何が得か）     |
| 環境 | どう遷移するか           |

マルコフ性: 次のことは現在状態のみで決定される。

> 教師あり学習の「データセット準備」に相当するのだが、強化学習の「環境と報酬設計」である

### 1.4 ベルマン方程式と価値関数

強化学習が目指すのは「これから先の報酬の合計」である。

収益（リターン）:

```text
Gt = rt+1 + γ·rt+2 + γ²·rt+3 + …
```

価値関数:

```text
V(s) = E[r + γ·V(S')]  (ベルマン方程式)
```

| 記号        | 意味                                             |
| :---------- | :----------------------------------------------- |
| γ（割引率） | どこまで先を見るか（0=近視眼、1=遠視だが不安定） |
| V(s)        | この状態から先、いくら儲かるかの見積もり         |
| Q(s,a)      | この状態でこの行動をとった場合の見積もり         |

ブートストラップの奇妙さ:
「未来の見積もりで現在の見積もりを更新」する。  
最初はデタラメだが、報酬という「本物報酬」1点から始まり、徐々に正確になる。

> 正解がない問題で学習が回る理由がここにある

## 2. 学習メカニズム

性質: 強化学習が実際にどのように昨日するかの仕組み。事前学習との役割分担から、具体的なアルゴリズムまでを扱う。

### 2.1 事前学習と強化学習の役割分担

LLMにおける2つの目的関数のズレ:

| 学習段階 | 目的関数                               |
| :------- | :------------------------------------- |
| 事前学習 | 「この続きに来る確率が高いのはどれか」 |
| 本来必要 | 「この人にとって一番良い応答はどれか」 |

事前学習は質問の「続き」を書く。支持従従、曖昧時の確認、危険依頼を断る - これらは事前学習の目的関数に含まれていない。

役割の明確化:

- 事前学習が「知識」を作る
- 強化学習が「振る舞い」を作る

> ChatGPT現象のプロセスで構成される（Christiano et al., 2017）

## 2.2 RLHF（人間フィードバックによる強化学習）

RLHFは3段階のプロセスで構成される（Christiano et al., 2017）

```text
Stage 1: SFT（教師あり微調整）
  → 人が書いた模範応答を真似る

           ↓

Stage 2: 報酬モデル学習
  → 複数応答を人間が順位付け、比較から点数を学習

           ↓

Stage 3: PPO強化学習
  → 報酬モデルのスコアを報酬に応答の出し方を変更
  → KL距離に罰則（報酬追従で言語が壊れるのを防ぐ）
```

人間の選好を利用する理由:

- 「80点」という絶対評価は困難
- 「AよりBが良い」という比較は安定して回答可能

**InstructGPT（2022）**の衝撃:

- 1.3B（RLHF適用）vs 175B（GPT-3素モデル）
- パラメータ130分の1以下なのに人間評価で上位
- 増えたのは知識ではなく「知識の向き方」

### 2.3 RLHFの発展形

**Constitutional AI / RLAIF (Anthropic 2022)** :

- 問題: RLHFには人間ラベルが必須だが、「断るべき依頼」を網羅できない
- 解決: 原則（constitution）を文章で与え、AI自身が自応答を批評・書き直す
- 報酬の出どころ: 人間 → 原則へシフト

**RLVR**（検証可能な報酬）:

- 数学・コードは正誤判定可能
- 教師あり微調整をスキップし、純粋なRLのみ

**DeepSeek-R1**（2025）:

- R1-Zeroは教師ありなしで学習
- 創発した振る舞い: 長考、自己検証、間違い気付き、考え直し
- 誰も「こう推論しろ」と教えない - 報酬は最終正誤のみ

> かつてRLは仕上げ工程だったが、現在は能力そのものを作る工程になった

### 2.4 報酬設計の自由度

アルゴリズムより報酬が効く - 報酬の形が、そのままAIの性格になる。

スパース報酬問題:

- ゴール到達で+1, 他は0
- ランダム方針はゴールに到達するまで報酬0
- 学習が始まらない

対策手法:

| 手法           | 内容                 | 注意点           |
| :------------- | :------------------- | :--------------- |
| Reward Shaping | 途中に報酬を設置     | 誤配置で事故     |
| 模倣学習       | 専門家の真似から開始 | 専門家データ必要 |
| 内発的動機付け | 好奇心を報酬に加算   | 設計が難しい     |

## 3. 応用事例

性質: 強化学習が実際に成果を上げた領域。ゲームから物質・設備、そして言語モデルへの適用までを扱う。

### 3.1 ゲームでの実績

強化学習の実績はまずゲームで出た。

| 年   | システム     | 成果                                             |
| :--- | :----------- | :----------------------------------------------- |
| 2015 | DQN          | Atariピクセル+スコアのみ、ルール未教示で人間超え |
| 2016 | AlphaGo      | 李世乭に4勝1敗                                   |
| 2017 | AlphaGo Zero | 人間棋譜ゼロ、自己対戦のみで前世代を上回る       |

衝撃的な発見: 「人間のデータがない方が強くなれる」

- 人間学習は加減保証と同時に上限にもなる
- 人が思いつかない手は棋譜に無い

> 人間評価を外せる領域では外す方が伸びる（ただし正解判定可能な領域に限定）

### 3.2 物理・設備への適用

現在、強化学習は物理と設備の側に移行している。

| 領域           | 内容                              | 出典              |
| :------------- | :-------------------------------- | :---------------- |
| データセンター | 冷却エネルギー約40%削減           | DeepMind 2016     |
| 核融合         | トカマクプラズマ形状制御          | Nature 2022       |
| 成層圏気球     | 風を読み無燃料で滞留              | Loon, Nature 2020 |
| 半導体・数学   | チップ設計/行列積アルゴリズム発見 | Nature 2021-22    |
| ロボット       | 四足歩行・把持・手先操作          | 各所              |
| 言語           | RLHF/RLVR                         | 2022~             |

効く条件: 「正解の手順は書けないが、良し悪しは測れる」問題

### 3.3 言語モデルへの適用

言語モデルにおける強化学習の役割は急速に拡大している。

従来（~2022）: 仕上げ工程としてのRLHF

- 事前学習済みモデルの「向き」を調整
- 有害出力の抑制、支持追従の向上

現在（2025~）: 能力製造工程としてのRL

- DeepSeek-R1: 推論能力そのものをRLで獲得
- Chain-of-Thought的な振る舞いが創発

## 4. 落とし穴と対策

性質: 強化学習で頻発する問題とその対処法。報酬設計の失敗事例から、根本的な解決策までを扱う。

### 4.1 報酬ハッキング

AIは間違えない。書いた目的を正確に最大化する。

事例: **CoastRunners (OpenAI, 2016)**

- 報酬: 「スコアを最大化」
- 結果: レースを放棄し、得点アイテムが復活する入江を延々周回
- スコア: 人間超え、順位: 最下位、船: 燃焼

```text
意図した振る舞い: レースに勝つ
実際の振る舞い: 得点アイテムを周回
報酬関数: スコア最大化
  → AIは報酬関数に対して「正しく」動いている
```

対策手法:

|            |                              |
| :--------- | :--------------------------- |
| 模倣学習   | 専門家の軌跡を教師ありで真似 |
| 逆強化学習 | 行動観察から報酬を逆算       |
| RLHF       | 模倣 + 比較 + RLの合わせ技   |

> 最重要: 「AIが変んなことをする時、AIは仕様通りに動いている。間違っているのは目的の書き方。」

### 4.2 「もっともらしい」と「役に立つ」の乖離

LLMのハルシネーションは報酬ハッキングの一種である。

- 事前学習の目的: 「もっともらしい続き」を生成
- ユーザーの期待: 「性格で役に立つ」応答

「もっともらしい続き」の最大化に対して、モデルは忠実に動作している。問題は目的関数の設計にある。

### 4.3 新規性探索

目的を捨てた方が、目的に速く着くことがある。

**手法の進化**

| 手法           | 年   | 内容                                             |
| :------------- | :--- | :----------------------------------------------- |
| ICM            | 2017 | 予測誤差を自己報酬化                             |
| RND            | 2018 | ランダムネットワーク蒸留                         |
| Novelty Search | 2011 | 目的関数ゼロ、「これまでと違う振る舞い」のみ評価 |

**Novelty search**の直感:

```text
ゴール追従: 壁の手前が「最も近い」→ 身動き不可
新規性のみ: 一度遠ざかる動きも「新しい」で評価される
```

> 地図なしでは「ゴールまでの距離」は計算できない。未知環境では新規性報酬が本命となる

## 5. 実践知見

性質: 実際に強化学習システムを構築した経験から得られた洞察。理論と実装のギャップを埋める知見を扱う。

### 5.1 研究経験からの学び

研究内容: 月面の縦孔と地下空洞を軍ロボットで分担探査（地図なし環境）

システム構造:

```text
Layer3: System Agent - 分岐・統合判断（学習）
Layer2: Swarm Agent * N = 誘導パラメータ（学習）
Layer1: Robot * 20 - 手設計アルゴリズム
```

実装した報酬項目:

| 項目       | 値                 | なければ起きること     |
| :--------- | :----------------- | :--------------------- |
| 時間経過   | -1                 | その場に止まる         |
| 探索率上昇 | +5 + 10·(上昇)^0.5 | 広げる動機なし         |
| 既踏地再訪 | -2                 | 同じ場所を往復して稼ぐ |
| 衝突       | -10                | 壁に突入               |
| 目標達成   | +50                | 途中で満足             |
| 未達終了   | -50                | Early Stopを習得       |

洞察: 項目が増えた箇所 = 失敗した場所。非線形化（平方根）も試行錯誤の帰結。

> 報酬に書いていないことは、守られない。これは失敗ではなく成功である。

### 5.3 学び②: 学習の外側では保証がない

- 保証範囲: 学習中の状態分布内のみ
- 外側では根拠なく出力する
- 「分からない」とは言わない（棄権選択肢がなければ存在しない）
- sim-to-real gap: シミュレータ完璧 ≠ 別地形で動作

対策: データ分布を広げる、または外部で検知する

### 5.4 学び③: 事前データが可能性の範囲を決める

- 手設計アルゴリズム = 「何ができるか」の範囲を決定
- 報酬 = 「どこへ向かうか」を決定

LLMへの適用:

| 問題                        | 原因             | 対処可能性               |
| :-------------------------- | :--------------- | :----------------------- |
| 知らないことを喋る/古い情報 | 事前学習側の限界 | プロンプトではカバー不可 |
| 指示無視/断る/長考          | 強化学習側の仕事 | データ量と無関係         |

> 「事前学習か、強化学習か」の切り分けで、ほぼ全挙動が説明可能になる

### 5.5 学び④: AIの限界は学習の前に決まっている

```text
作る側からの見え方
  ・状態S（何を見せるか）
  ・行動A（何ができるか）
  ・報酬R（何が得か）
  ・環境（何が起きるか）

  → 決めた瞬間に、できること/できないことの限界は確定

使う側からの見え方
  ・入れたら何か返ってくる箱
```

一般化: 「なぜこうなるのか」と思ったら、S・A・R・環境の4つに翻訳する。大抵そこに答えがある。

### 5.6 実装で挙動が変わる箇所

| 要素             | 変更による影響                     |
| :--------------- | :--------------------------------- |
| 状態定義         | 1つ削るだけで解けなくなる          |
| 行動定義         | 離散/連続/粒度で戦略の形が変わる   |
| 方策 vs 価値関数 | 同じ環境でも学習速度・安定性が別物 |

## まとめ: 3つの核心

1. 事前学習が「知識」を作り、強化学習が「振る舞い」を作る。最近は推論能力そのものも強化学習が製造。
2. 強化学習は「正解を教えず、評価だけで教える」学び方。「正解手順は書けないが良し悪しは測れる」問題に効く。逆なら教師あり学習が速い。
3. AIが変なことするとき、AIは仕様通りに動いている。「なぜ間違えたか」ではなく「何を最大化させたか」で見る。
